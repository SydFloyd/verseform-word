# Verseform for Word — Decisions

Record durable choices here. Supersede a row rather than rewriting history after code depends on it.

| ID | Status | Decision | Reason |
|---|---|---|---|
| `D-001` | Accepted | Use **Verseform for Word** as the working product name and `verseform-word` as the repository name. | It preserves the trusted Verseform interaction while clearly naming the host; branding can transfer with the repository later. |
| `D-002` | Accepted | Build one TypeScript Office.js task-pane add-in for Word on the web first and supported Word desktop hosts second. Use an add-in-only XML manifest until Microsoft's unified Word manifest is production-supported. | Microsoft documents task-pane add-ins as cross-platform, while the unified Word manifest remains preview-only. Two implementations would create needless drift. |
| `D-003` | Accepted as a gated direction | Target WordApi 1.7 native annotations for inline feedback plus hover/click events, with preview and explicit insertion in the task pane. Make VFW-010 prove exact offsets, duplicate references, replacement, Undo, lifecycle, and the stale-operation boundary in real Word on the web. | Annotations are the closest native mapping to Verseform, but Word owns the canvas and the APIs require a connected Microsoft 365 subscription. Popup-action APIs are WordApi 1.8, and 1.7 offers no demonstrated atomic conditional replacement. |
| `D-004` | Accepted | Own a pure local detector behind a Word-neutral contract. Start from Verseform's strict English behavior; treat DBS's MIT detector as optional reference material and never load its remote DOM/popup bundle in production. | The DBS detector brings excellent multilingual data but its webpage mutation, permissive grammar, and HTML popup are not the Word host or correctness boundary. |
| `D-005` | Accepted | Bundle no Bible text. Detection remains available offline, while preview and insertion require authorized DBS access and fail explicitly when unavailable. | This matches the owner's direction and prevents text from being mislabeled or silently substituted. |
| `D-006` | Accepted | Add no account, telemetry, crash upload, advertising, AI prose service, document upload, or background scanning. | A writing aid should not turn private Word content into operational data. |
| `D-007` | Accepted | Honor a saved authorized translation; otherwise prefer a catalog entry identified as NASB, then the first valid catalog entry. | This carries the proven Verseform default without bundling a fallback translation. |
| `D-008` | Accepted | License the source under MIT and keep the repository under `SydFloyd` while building. Any later DBS mirror or transfer remains an explicit coordination step. | This permits free use and contribution without prematurely assigning publisher authority. |
| `D-009` | Accepted | Ship the first usable release in English, then add languages only after language-specific detection corpora and Word offset proof pass. | A narrow walking slice protects accuracy while preserving a deliberate route to DBS's multilingual reach. |
| `D-010` | Accepted | DBS's cache permission applies to this add-in. Persistent provider caches must be local, bounded by age/bytes/entries, schema-versioned, clearable, and contain only authorized catalog or Scripture responses—never document prose. | Caching can improve responsiveness and resilience without widening document-data authority. |
| `D-011` | Pending owner/DBS input | Choose the production HTTPS host, server-log retention, support URL, and Microsoft Marketplace publisher identity. | These values are user-visible trust and privacy boundaries, not deployment trivia. |
| `D-012` | Accepted for VFW-010, feasibility still gated | Do not add a long SharedRuntime as a pane-close cleanup substitute yet. Use a bounded local ledger of exact Verseform-returned annotation IDs, atomically reserve its capacity before a host create, and apply locked delta updates before a reopened runtime binds Word events. Retain IDs affected by a live paragraph refresh, replacement, or annotation-removal event until the live runtime ends; never evict one merely to make room for another marker. | SharedRuntime can keep code and listeners alive while hidden, but the available Microsoft documentation only explicitly ties its visibility event to programmatic hide/show. Native close behavior is still a host proof gate, and hidden background scanning would violate the local-first interaction contract. Same-runtime retention safely revalidates an Undo-resurrected exact ID without persisting prose, but after pane close the required range/source metadata is gone. WordApi 1.7 cannot safely map a later resurrected ID or sweep by appearance, and capacity exhaustion must fail closed. |
