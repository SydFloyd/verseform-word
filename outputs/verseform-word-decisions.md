# Verseform for Word — Decisions

Record durable choices here. Supersede a row rather than rewriting history after code depends on it.

| ID | Status | Decision | Reason |
|---|---|---|---|
| `D-001` | Accepted | Use **Verseform for Word** as the working product name and `verseform-word` as the repository name. | It preserves the trusted Verseform interaction while clearly naming the host; branding can transfer with the repository later. |
| `D-002` | Accepted | Build one TypeScript Office.js task-pane add-in for Word on the web first and supported Word desktop hosts second. Use an add-in-only XML manifest until Microsoft's unified Word manifest is production-supported. | Microsoft documents task-pane add-ins as cross-platform, while the unified Word manifest remains preview-only. Two implementations would create needless drift. |
| `D-003` | Accepted; interaction extended by `D-014`, `D-019`, and `D-025` | Target WordApi 1.7 native annotations for inline feedback plus activation events, with preview and explicit insertion in the task pane. Make VFW-010 prove exact offsets, duplicate references, replacement, Undo, and lifecycle in real Word on the web. | Annotations are the closest native mapping to Verseform, but Word owns the canvas and the APIs require a connected Microsoft 365 subscription. VFW-010 established the safe baseline; `D-025` supplies the required pane-free command when a host withholds annotation activation. |
| `D-004` | Accepted | Own a pure local detector behind a Word-neutral contract. Start from Verseform's strict English behavior; treat DBS's MIT detector as optional reference material and never load its remote DOM/popup bundle in production. | The DBS detector brings excellent multilingual data but its webpage mutation, permissive grammar, and HTML popup are not the Word host or correctness boundary. |
| `D-005` | Accepted | Bundle no Bible text. Detection remains available offline, while preview and insertion require authorized DBS access and fail explicitly when unavailable. | This matches the owner's direction and prevents text from being mislabeled or silently substituted. |
| `D-006` | Accepted | Add no account, telemetry, crash upload, advertising, AI prose service, document upload, or background scanning. | A writing aid should not turn private Word content into operational data. |
| `D-007` | Accepted | Honor a saved authorized translation; otherwise prefer a catalog entry identified as NASB, then the first valid catalog entry. | This carries the proven Verseform default without bundling a fallback translation. |
| `D-008` | Accepted | License the source under MIT and keep the repository under `SydFloyd` while building. Any later DBS mirror or transfer remains an explicit coordination step. | This permits free use and contribution without prematurely assigning publisher authority. |
| `D-009` | Accepted | Ship the first usable release in English, then add languages only after language-specific detection corpora and Word offset proof pass. | A narrow walking slice protects accuracy while preserving a deliberate route to DBS's multilingual reach. |
| `D-010` | Accepted | DBS's cache permission applies to this add-in. Persistent provider caches must be local, bounded by age/bytes/entries, schema-versioned, clearable, and contain only authorized catalog or Scripture responses—never document prose. | Caching can improve responsiveness and resilience without widening document-data authority. |
| `D-011` | Pending owner/DBS input | Choose the production HTTPS host, server-log retention, support URL, and Microsoft Marketplace publisher identity. | These values are user-visible trust and privacy boundaries, not deployment trivia. |
| `D-012` | Superseded by `D-015` | Do not add a long SharedRuntime as a pane-close cleanup substitute yet. Use a bounded local ledger of exact Verseform-returned annotation IDs, atomically reserve its capacity before a host create, and apply locked delta updates before a reopened runtime binds Word events. Retain IDs affected by a live paragraph refresh, replacement, or annotation-removal event until the live runtime ends; never evict one merely to make room for another marker. | This was the gated VFW-010 lifecycle direction. The completed host walk and the explicit opaque-ID refusal in `D-015` now define the accepted behavior and remaining limitation. |
| `D-013` | Accepted platform limitation | Keep the exact final paragraph/annotation/range/Created-state recheck and one `Range.insertText(..., "Replace")` transaction, but do not claim atomic stale safety against a coauthor edit between validation sync and replacement sync. | WordApi 1.7 exposes no atomic conditional replacement. Microsoft documents paragraph changes—but not annotation click, hover, or removal—as coauthor-triggered, so events cannot close that timing window. The owner accepted this narrow, documented platform limitation; observable stale, missing, ambiguous, and failed cases still fail closed. |
| `D-014` | Accepted; pane-free gate superseded by `D-025` | Support annotation activation by click and Word's `Alt+Down` command. Keep hover handling as a best-effort convenience, but do not gate preview or release on hover delivery. | WordApi 1.7 documents these events, but host delivery differs. Word on the web proved click and keyboard activation; the Windows host later withheld both while the pane was hidden, so `D-025` owns the reliable pane-free action. |
| `D-015` | Accepted | Close the VFW-010 lifecycle gate with the bounded exact-ID ledger, the proved simultaneous-document and pane close/reopen behavior, and an explicit no-change refusal when a prior runtime's opaque annotation ID returns without recoverable range/source metadata. Do not add SharedRuntime or persist document prose to repair that unsupported case. | Real Word on the web preserved independent panes, resumed detection after close/reopen, and returned a safe current marker after post-close Undo. The alternate prior-ID branch is deterministic proof: WordApi 1.7 cannot safely reconstruct its forgotten ownership metadata, so refusal is the only truthful action. |
| `D-016` | Accepted; insertion presentation superseded by `D-020` | Use the credential-free DBS ARC Bible-text API directly from the task pane, with a strict GET-only coordinate transport and a separate local schema-versioned content cache capped at 65 entries/4 MiB (24-hour catalog, seven-day chapters). Insert provider attribution as visible editable text with the passage and citation. | DBS permits caching, ARC supports the required browser CORS boundary, and the catalog supplies both authorization and attribution. `D-020` retains the provider notice in the optional pane while removing its repetition after every quotation. |
| `D-017` | Accepted | Close VFW-030 as an English-only hardening slice and defer all multilingual detection implementation until DBS has tested and approved the product direction and the English pilot user has supplied practical feedback. A later language still requires its own corpus and Word offset proof. | The owner explicitly chose feedback before breadth. This prevents speculative language work, keeps detection locally auditable, and lets DBS and a real English writer shape the next capability before resources are spent. |
| `D-018` | Accepted | Use Microsoft's pinned `office-addin-debugging` command on demand for Word for Windows sideload sessions, unregister every session explicitly, and do not retain its current vulnerable development-only dependency tree in the project graph or ship it in release assets. | The official tool owns Windows registration and cleanup, but version 6.1.2 currently introduces 539 packages and eight high-severity development advisories. A pinned transient bridge keeps the desktop proof reproducible without widening the production or committed dependency boundary. |
| `D-019` | Accepted; pane behavior superseded by `D-020` | Optimize the Scripture-heavy writing loop as **hover previews; click or `Alt+Down` inserts through the existing guarded command**. Reuse a ready or in-flight preview for the same annotation and translation, keep task-pane Insert as an alternative, and do not use WordApi 1.8 critique suggestions as custom command buttons. | The Windows pilot immediately exposed the pane mouse trip as friction. Direct annotation intent matches Verseform's original interaction and still requires an explicit user action plus the full stale check. Word's 1.8 popup suggestions are Word-owned document replacements, so treating a label such as “Insert passage” as a command could replace prose outside Verseform's exact guarded range operation. |
| `D-020` | Accepted; startup interaction superseded by `D-026`, insertion path extended by `D-025` | Use one long SharedRuntime 1.1 runtime so **Enable Verseform** starts pane-free detection and **Preview & Settings** remains optional. Hidden-pane hover performs no provider work; visible-pane hover may preview, while explicit insertion uses the guarded command. Insert passage plus compact translation citation only; retain the complete provider notice in the optional pane instead of appending it after every quotation. | The Windows pilot found both the persistent pane and repeated copyright paragraph intrusive during high-volume Scripture work. Microsoft documents that a long shared runtime continues after the pane closes. `D-025` makes the explicit command independent of hidden annotation event delivery, and `D-026` removes the now-redundant enable step. |
| `D-021` | Accepted | Treat a Word paragraph break as a delimiter only from structural host evidence: map `onParagraphAdded` to its exact preceding paragraph, reread that paragraph and whether a following paragraph exists, and append a newline only inside the pure detection input. | Word omits paragraph marks from `Paragraph.text`. Treating every paragraph end as complete activates a reference before the writer types a delimiter; relying only on paragraph-changed events misses Enter. The paired event plus structural reread preserves both requirements and exact UTF-16 ranges. |
| `D-022` | Accepted; enable-command portion superseded by `D-026` | Complete **Enable Verseform**'s Office command event before asynchronous shared-runtime startup work, and reveal the optional pane only when an explicit click/keyboard Scripture request fails while it is hidden. | Holding the command queue during event binding and catalog access makes repeated clicks appear necessary. A long shared runtime survives command completion. Silent provider failures are unacceptable, while opening the pane during normal operation would reintroduce the pilot's persistent-panel friction. `D-026` later removes that command entirely. |
| `D-023` | Accepted lifecycle rule; causal claim corrected | Never treat task-pane `pagehide`, unload, or visibility as shared-runtime destruction. Pane visibility controls only optional hover preview; it must not call `controller.stop()` or remove Word event handlers. Reserve teardown for an actual controller/runtime lifetime boundary, with the exact-ID ledger covering abrupt loss. | The old callback contradicted the intended long-runtime lifetime, but removing it did not fix the reported behavior. The 2026-09-06 native comparison observed no `pagehide`, a surviving runtime, continuing paragraph events, and exact `Created` annotations while hidden; Word delivered annotation clicks only with the pane visible. Do not repeat the earlier unsupported claim that teardown was the established root cause. |
| `D-024` | Accepted validation boundary; interaction alternative accepted in `D-025` | Configure one long runtime with matching runtime/function/task-pane resource IDs and no `TaskpaneId`, as Microsoft requires. Run real-host proofs against built scripts and external CSS under the production CSP, not Vite's blocked inline-style/HMR client. Treat native annotation interaction independently from shared-runtime survival. | Live Windows debugging found both a manifest configuration error and CSP-blocked development styles/reload. Correcting those did not itself fix hidden annotation events, so `D-025` adds a separate explicit action rather than weakening intent with replacement on selection change. |
| `D-025` | Accepted | Make Word's ribbon and selected-text context menu expose **Fill Scripture** as the reliable pane-free insertion path. Resolve the containing or immediately preceding reference locally; the explicit command may complete a valid reference at paragraph end even when Word omits its trailing delimiter. Refresh and annotate that exact candidate, reuse the existing translation request and final source/range/Created-state checks, and perform one guarded Replace. Keep annotation click/`Alt+Down` as host-dependent conveniences. Do not ship a custom shortcut claim until it is proved in the target host. | The owner approved the command alternative after the installed Windows host repeatedly withheld hidden annotation click/hover events. Real Word then replaced `John 3:16` with NASB and citation from the ribbon while the pane was closed and one Undo restored the reference. Three clean shortcut-manifest reloads, including Microsoft's current sample key and JSON shape, did not register an add-in shortcut in this sideload session; removing the unproved claim is safer than overriding a user's Office shortcut preferences. |
| `D-026` | Accepted | Remove **Enable Verseform** rather than turn it into a toggle. **Fill Scripture** and **Preview & Settings** each start the one shared runtime idempotently when needed; no separate background state or load-on-reopen preference is exposed. On the next runtime start, conditionally clear an earlier build's saved `Load` preference without making that migration a startup dependency. | Fill is the reliable pane-free action and already owns lazy startup. Native hidden annotation activation is unavailable in the tested Windows host, so a persistent enable mode adds UI and background work without improving the writer's dependable path. The migration prevents old documents from retaining a mode that the current UI no longer represents. |
| `D-027` | Superseded by `D-028` | Limit one reference to a single verse or a same-chapter range of at most 25 verses. Enforce the rule in the pure classifier and again before provider/cache access, and explain it with the daily workflow in Preview & Settings. | The initial conservative limit was later expanded at owner direction so a writer can insert any complete chapter. |
| `D-028` | Accepted | Permit any valid same-chapter reference, including Psalm 119:1–176. Let canonical chapter bounds own user-facing validation and retain a 176-verse provider guard before cache/network access for callers outside the parser. Explain the one-chapter boundary in Preview & Settings. | A complete chapter is a natural writer-facing unit, Psalm 119 is the largest chapter in the 66-book canon, and the independent provider ceiling keeps requests bounded without arbitrarily splitting valid chapters. |
| `D-029` | Accepted | Use Microsoft Marketplace through Partner Center's Microsoft 365 and Copilot program for public distribution. Use Microsoft 365 Integrated Apps only for a controlled tenant pilot. Treat every Word platform admitted by the manifest—currently web, Windows, and Mac—as a certification target, and do not publish until the hosted-origin, accessibility, and Mac walks pass. | Marketplace is the supported public Office Add-in channel and makes the add-in discoverable inside Word. Microsoft's certification policy requires an add-in to work on every platform its manifest admits and does not permit runtime platform rejection as a substitute. |
| `D-030` | Accepted | Use `https://verseform-word.kmproto.com` as the owner-approved friend-pilot application origin. Publish a version-matched downloadable XML manifest and plain-language `/install` page there, with **Verseform Project** as the temporary provider until DBS authorizes its final publisher identity. Treat manual Word-web upload as browser-profile-local testing, not desktop, tenant, or Marketplace installation. | The existing Verseform site establishes Vercel plus a `kmproto.com` subdomain as the lowest-cost operated path. A dedicated origin keeps Office CSP, assets, caching, and release identity separate while making one-person testing substantially easier without overstating persistence. |
