# Verseform for Word — Decisions

Record durable choices here. Supersede a row rather than rewriting history after code depends on it.

| ID | Status | Decision | Reason |
|---|---|---|---|
| `D-001` | Accepted | Use **Verseform for Word** as the working product name and `verseform-word` as the repository name. | It preserves the trusted Verseform interaction while clearly naming the host; branding can transfer with the repository later. |
| `D-002` | Accepted | Build one TypeScript Office.js task-pane add-in for Word on the web first and supported Word desktop hosts second. Use an add-in-only XML manifest until Microsoft's unified Word manifest is production-supported. | Microsoft documents task-pane add-ins as cross-platform, while the unified Word manifest remains preview-only. Two implementations would create needless drift. |
| `D-003` | Accepted; interaction extended by `D-014` and `D-019` | Target WordApi 1.7 native annotations for inline feedback plus activation events, with preview and explicit insertion in the task pane. Make VFW-010 prove exact offsets, duplicate references, replacement, Undo, and lifecycle in real Word on the web. | Annotations are the closest native mapping to Verseform, but Word owns the canvas and the APIs require a connected Microsoft 365 subscription. VFW-010 established the safe baseline; `D-019` refines its high-throughput interaction without changing the replacement boundary. |
| `D-004` | Accepted | Own a pure local detector behind a Word-neutral contract. Start from Verseform's strict English behavior; treat DBS's MIT detector as optional reference material and never load its remote DOM/popup bundle in production. | The DBS detector brings excellent multilingual data but its webpage mutation, permissive grammar, and HTML popup are not the Word host or correctness boundary. |
| `D-005` | Accepted | Bundle no Bible text. Detection remains available offline, while preview and insertion require authorized DBS access and fail explicitly when unavailable. | This matches the owner's direction and prevents text from being mislabeled or silently substituted. |
| `D-006` | Accepted | Add no account, telemetry, crash upload, advertising, AI prose service, document upload, or background scanning. | A writing aid should not turn private Word content into operational data. |
| `D-007` | Accepted | Honor a saved authorized translation; otherwise prefer a catalog entry identified as NASB, then the first valid catalog entry. | This carries the proven Verseform default without bundling a fallback translation. |
| `D-008` | Accepted | License the source under MIT and keep the repository under `SydFloyd` while building. Any later DBS mirror or transfer remains an explicit coordination step. | This permits free use and contribution without prematurely assigning publisher authority. |
| `D-009` | Accepted | Ship the first usable release in English, then add languages only after language-specific detection corpora and Word offset proof pass. | A narrow walking slice protects accuracy while preserving a deliberate route to DBS's multilingual reach. |
| `D-010` | Accepted | DBS's cache permission applies to this add-in. Persistent provider caches must be local, bounded by age/bytes/entries, schema-versioned, clearable, and contain only authorized catalog or Scripture responses—never document prose. | Caching can improve responsiveness and resilience without widening document-data authority. |
| `D-011` | Pending owner/DBS input | Choose the production HTTPS host, server-log retention, support URL, and Microsoft Marketplace publisher identity. | These values are user-visible trust and privacy boundaries, not deployment trivia. |
| `D-012` | Superseded by `D-015` | Do not add a long SharedRuntime as a pane-close cleanup substitute yet. Use a bounded local ledger of exact Verseform-returned annotation IDs, atomically reserve its capacity before a host create, and apply locked delta updates before a reopened runtime binds Word events. Retain IDs affected by a live paragraph refresh, replacement, or annotation-removal event until the live runtime ends; never evict one merely to make room for another marker. | This was the gated VFW-010 lifecycle direction. The completed host walk and the explicit opaque-ID refusal in `D-015` now define the accepted behavior and remaining limitation. |
| `D-013` | Accepted platform limitation | Keep the exact final paragraph/annotation/range/Created-state recheck and one `Range.insertText(..., "Replace")` transaction, but do not claim atomic stale safety against a coauthor edit between validation sync and replacement sync. | WordApi 1.7 exposes no atomic conditional replacement. Microsoft documents paragraph changes—but not annotation click, hover, or removal—as coauthor-triggered, so events cannot close that timing window. The owner accepted this narrow, documented platform limitation; observable stale, missing, ambiguous, and failed cases still fail closed. |
| `D-014` | Accepted | Require annotation activation by click and Word's `Alt+Down` command. Keep hover handling as a best-effort convenience, but do not gate preview or release on hover delivery. | WordApi 1.7 documents a hover event, yet the final Word on the web walk did not deliver it under trusted pointer movement. Click and keyboard activation were repeatably proved and preserve an accessible, predictable path. |
| `D-015` | Accepted | Close the VFW-010 lifecycle gate with the bounded exact-ID ledger, the proved simultaneous-document and pane close/reopen behavior, and an explicit no-change refusal when a prior runtime's opaque annotation ID returns without recoverable range/source metadata. Do not add SharedRuntime or persist document prose to repair that unsupported case. | Real Word on the web preserved independent panes, resumed detection after close/reopen, and returned a safe current marker after post-close Undo. The alternate prior-ID branch is deterministic proof: WordApi 1.7 cannot safely reconstruct its forgotten ownership metadata, so refusal is the only truthful action. |
| `D-016` | Accepted | Use the credential-free DBS ARC Bible-text API directly from the task pane, with a strict GET-only coordinate transport and a separate local schema-versioned content cache capped at 65 entries/4 MiB (24-hour catalog, seven-day chapters). Insert provider attribution as visible editable text with the passage and citation. | DBS permits caching, ARC supports the required browser CORS boundary, and the catalog supplies both authorization and attribution. A proxy would add document-adjacent infrastructure and logs without improving this slice; visible attribution travels with copied or saved Word content and does not depend on hidden metadata. |
| `D-017` | Accepted | Close VFW-030 as an English-only hardening slice and defer all multilingual detection implementation until DBS has tested and approved the product direction and the English pilot user has supplied practical feedback. A later language still requires its own corpus and Word offset proof. | The owner explicitly chose feedback before breadth. This prevents speculative language work, keeps detection locally auditable, and lets DBS and a real English writer shape the next capability before resources are spent. |
| `D-018` | Accepted | Use Microsoft's pinned `office-addin-debugging` command on demand for Word for Windows sideload sessions, unregister every session explicitly, and do not retain its current vulnerable development-only dependency tree in the project graph or ship it in release assets. | The official tool owns Windows registration and cleanup, but version 6.1.2 currently introduces 539 packages and eight high-severity development advisories. A pinned transient bridge keeps the desktop proof reproducible without widening the production or committed dependency boundary. |
| `D-019` | Accepted | Optimize the Scripture-heavy writing loop as **hover previews; click or `Alt+Down` inserts through the existing guarded command**. Reuse a ready or in-flight preview for the same annotation and translation, keep task-pane Insert as an alternative, and do not use WordApi 1.8 critique suggestions as custom command buttons. | The Windows pilot immediately exposed the pane mouse trip as friction. Direct annotation intent matches Verseform's original interaction and still requires an explicit user action plus the full stale check. Word's 1.8 popup suggestions are Word-owned document replacements, so treating a label such as “Insert passage” as a command could replace prose outside Verseform's exact guarded range operation. |
