## Last verified

- Microsoft documents Word task-pane add-ins as cross-platform across web and desktop hosts.
- The installed Office.js type contract exposes `onParagraphChanged` in WordApi 1.6 and native annotation insertion, hover, click, and removal events in WordApi 1.7. It marks annotation popup-action options/events as WordApi 1.8. Annotation state is ephemeral and requires a connected Microsoft 365 subscription.
- Microsoft's unified manifest remains preview-only for Word production add-ins, so this seed uses an add-in-only XML manifest.
- DBS's BrowserBible verse detector is MIT-licensed and offers a pure multilingual detector, but its broader DOM/popup system and permissive reference grammar do not automatically fit the Word correctness boundary. No DBS detector source is incorporated in this seed.
- VFW-010's local controller uses one returned annotation ID per candidate, a generation-guarded start/stop runtime, task-pane preview/Insert/clear-selection fallback, labeled non-Scripture test text, a full paragraph/source/offset/Created-state recheck, and one Word range-replace command. It intentionally makes no DBS request. Its browser ledger uses same-origin locking and reread/delta writes; locking must be available before Word events bind. It atomically reserves one of at most 256 opaque slots before a host create, then commits the returned ID before publishing it as actionable, so simultaneous panes cannot overwrite ownership or overbook capacity. The reservation is not a recoverable owner record: a crash after Word creates an annotation but before commit can still leave an unowned marker. While a pane is alive, exact annotations removed during a refresh/replacement/removal event remain in a runtime-only retired map and retain their opaque ledger ID; they are reactivated only after Word proves their ID, `Created` state, paragraph, UTF-16 range, and source match. The controller never evicts them to make capacity: new markers fail closed. Stop attempts active and retired exact-ID cleanup without aging either. On startup, even a confirmed exact delete remains in the ledger; only a later startup result that says the ID is missing ages it, up to eight sweeps, so Word Undo cannot be treated as impossible. After pane close the required range/source metadata is deliberately forgotten. If an opaque ID loaded at startup later activates, the pane calls it a previous temporary annotation and refuses to map, alter, or delete it; this makes a late resurrection distinguishable without guessing its range. A malformed browser record blocks without overwriting the ledger. It attempts host cleanup per annotation ID and fails closed if the host reports that old markers could not be cleared; it does not scan or delete annotations by appearance. This is not a claim that cleanup succeeds in Word on the web.
- The completed Word on the web walk proved delimiter detection after a leading UTF-16 surrogate pair, duplicate-reference activation, exact replacement, one-step Undo, same-runtime Undo resurrection repair, one close/reopen-before-Undo ordering, readable dark-theme rendering, and safe operation across two simultaneous documents and task panes. In the final cross-document pass, `Document 2` detected `John 1:1` while `Document 1` retained three references; returning to `Document 1` still opened the exact preview. Closing and reopening the second pane, then typing another delimiter, restored detection. A standalone browser rendered the unsupported-host message with disabled controls and focus on its live status. The final insert → close → reopen → Undo sequence restored `John 1:1` and activated a current safe preview; Word did not surface the older opaque ID in that run, while the deterministic prior-ID branch proves the explicit no-change refusal if it does. Trusted pointer movement over the annotation did not deliver Word's documented hover event, so `D-014` retains it only as a best-effort convenience; click and `Alt+Down` are the proved activation paths. Windows forced-colors and a screen reader remain release-host validation.
- VFW-020 now uses a strict direct-browser DBS ARC boundary. The local version-one content cache holds at most 65 entries/4 MiB, expires the catalog after 24 hours and chapters after seven days, and is user-clearable without removing the separate translation preference. Schema/size/origin/coordinate/cancellation and malformed-payload tests keep document prose outside both request and storage inputs. Recorded payload regressions cover provider newlines, glued punctuation, trailing section headings, wrong book/chapter keys (including numbered-book ambiguity), and the singleton empty-chapter sentinel. The static 66-book DBS section-code table is the only BrowserBible detector artifact incorporated and its upstream MIT license is preserved in `NOTICE.md`.
- The VFW-020 Word on the web walk loaded 1,313 authorized translations and selected NASB by default. Activating `John 3:16` fetched and displayed NASB with Lockman attribution; one action inserted passage, editable citation, and attribution, and one Undo restored the reference. Reopening used the local cache; clearing it caused a fresh DBS fetch. Switching to KJV fetched the KJV passage and Public Domain attribution. Selecting the authorized Genesis-only Amele translation produced a clear unavailable state while copied Word content remained unchanged. Activating an uncached NET request and immediately changing the paragraph to `John 3:16 changed` left no preview or replacement; the reference remained local and the document was restored to `John 3:16` with NASB selected after the proof.
- The local fake-host, Office-adapter-double, fake-browser-lock, and DOM-harness suite proves delimiter gating, UTF-16 offsets, hover duplicate-ID mapping without a request when Word delivers the event, insert/clear race refusal, stale/unknown/removed-ID refusal, simulated partial cleanup failure/retry, deferred-reservation stop refusal, forced-unload/reopen exact-ID recovery, cross-document missing-ID retention without stop aging, opaque prior-ID post-close refusal, bounded retry, malformed-ledger fail-closed behavior, Browser ownership reread-under-lock concurrent claims/interleaved deltas/final-slot capacity, same-runtime revalidation of selected and non-selected IDs from an Undo-resurrected paragraph marker set (including late activation and exact duplicate cleanup), created-state gateway gating, no controller network call, additive-handler teardown attempts, unsupported/readiness host copy, task-pane live-region/status-focus/cancel wiring, and light/dark/forced-color declarations. It proves only those simulated contracts—not visual forced-colors or screen-reader behavior, browser lock/storage support in every target host, recovery of lost post-close paragraph metadata, or that a coauthor cannot edit between the final check and the replace sync.
- `npm run check` passes: strict typecheck, all 61 tests (four reference-core, forty-five Word/controller/UI, and twelve Scripture/provider/cache), production build, and the local structural manifest contract.
- Microsoft's Word event table records that paragraph changes are coauthor-triggered but annotation click, hover, and removal are not.
