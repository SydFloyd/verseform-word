## Last verified

- Microsoft documents Word task-pane add-ins as cross-platform across web and desktop hosts.
- The installed Office.js type contract exposes `onParagraphChanged` in WordApi 1.6 and native annotation insertion, hover, click, and removal events in WordApi 1.7. It marks annotation popup-action options/events as WordApi 1.8. Annotation state is ephemeral and requires a connected Microsoft 365 subscription.
- Microsoft's unified manifest remains preview-only for Word production add-ins, so this seed uses an add-in-only XML manifest.
- DBS's BrowserBible verse detector is MIT-licensed and offers a pure multilingual detector, but its broader DOM/popup system and permissive reference grammar do not automatically fit the Word correctness boundary. No DBS detector source is incorporated in this seed.
- VFW-010's local controller uses one returned annotation ID per candidate, a generation-guarded start/stop runtime, task-pane preview/Insert/clear-selection fallback, labeled non-Scripture test text, a full paragraph/source/offset/Created-state recheck, and one Word range-replace command. It intentionally makes no DBS request. Its browser ledger uses same-origin locking and reread/delta writes; locking must be available before Word events bind. It atomically reserves one of at most 256 opaque slots before a host create, then commits the returned ID before publishing it as actionable, so simultaneous panes cannot overwrite ownership or overbook capacity. The reservation is not a recoverable owner record: a crash after Word creates an annotation but before commit can still leave an unowned marker. While a pane is alive, exact annotations removed during a refresh/replacement/removal event remain in a runtime-only retired map and retain their opaque ledger ID; they are reactivated only after Word proves their ID, `Created` state, paragraph, UTF-16 range, and source match. The controller never evicts them to make capacity: new markers fail closed. Stop attempts active and retired exact-ID cleanup without aging either. On startup, even a confirmed exact delete remains in the ledger; only a later startup result that says the ID is missing ages it, up to eight sweeps, so Word Undo cannot be treated as impossible. After pane close the required range/source metadata is deliberately forgotten, so the stored ID can be exact-swept if present at startup but cannot safely map an Undo resurrection that occurs later. A malformed browser record blocks without overwriting the ledger. It attempts host cleanup per annotation ID and fails closed if the host reports that old markers could not be cleared; it does not scan or delete annotations by appearance. This is not a claim that cleanup succeeds in Word on the web.
- The initial real Word on the web run observed delimiter detection after a leading UTF-16 surrogate pair, duplicate-reference activation, explicit replacement, and Word Undo, but found a stale annotation after close/reopen. A later run showed that Undo can resurrect a whole prior native annotation set: after replacing the second duplicate and undoing, keyboard activation on untouched `John 1:1` reached an old unknown ID. The repaired run then repeated the same paragraph and replacement. One Undo restored the exact prose; after reconciliation Word reported three references, `Alt+Down` on restored `John 1:1` reached its preview, and the restored second `John 3:16` also reached its preview. The visible page showed one underline per reference. The run then inserted again, closed and reopened the pane before Undo, undid after reopening, reported three references, and keyboard-activated both an untouched and the restored duplicate without an unknown-ID refusal. That single ordering does not reveal which native ID Word activated and is not proof for every late resurrection ordering. The corrected task pane also rendered readable text, controls, disabled states, and focus in Word's dark theme; Windows forced-colors and a screen reader were not available.
- The local fake-host, Office-adapter-double, fake-browser-lock, and DOM-harness suite proves delimiter gating, UTF-16 offsets, duplicate-ID mapping, insert/clear race refusal, stale/unknown/removed-ID refusal, simulated partial cleanup failure/retry, deferred-reservation stop refusal, forced-unload/reopen exact-ID recovery, cross-document missing-ID retention without stop aging, bounded retry, malformed-ledger fail-closed behavior, Browser ownership reread-under-lock concurrent claims/interleaved deltas/final-slot capacity, same-runtime revalidation of selected and non-selected IDs from an Undo-resurrected paragraph marker set (including late activation and exact duplicate cleanup), generated-test-citation exclusion, created-state gateway gating, no controller network call, additive-handler teardown attempts, burst serialization, task-pane live-region/cancel/focus wiring, and light/dark/forced-color declarations. It proves only those simulated contracts—not Word on the web visual contrast or screen-reader behavior, browser lock/storage support in the target hosts, post-close Undo identity recovery, or that a coauthor cannot edit between the final check and the replace sync.
- `npm run check` passes: strict typecheck, thirty-nine detector/freshness/interaction tests, production build, and the local structural manifest contract.
- `npm audit --audit-level=high` reports zero vulnerabilities.
